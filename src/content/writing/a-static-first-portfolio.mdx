A project page has a straightforward job: show the work, explain the decisions, and make the next step easy to find. Most of that job does not need a running client-side application.

This site takes a static-first approach. Astro renders pages at build time. MDX holds case studies and articles. Typed Content Collections validate the metadata before it reaches a layout.

## Give content a contract

Each project has a title, description, category, technologies, year, and status. Optional media and links provide room for a project to grow without requiring every entry to invent the same evidence.

The body remains flexible. A robotics project can explain a measurement pipeline; an artificial-life project can explain controls and uncertainty. A shared layout gives them a common reading rhythm without forcing identical stories.

## Spend JavaScript deliberately

Filtering projects and changing the color theme require small browser interactions. The signal-sampling lab adds a focused interactive diagram. Reading a case study does not require hydrating a component tree.

The project list remains available without scripting. Fonts are served locally. Images have explicit dimensions and responsive sources. Reduced motion is part of the shared style system.

## Start from an architecture, then give it an identity

The foundation adapts [Case](https://github.com/erlandv/case), an MIT-licensed Astro theme organized around case studies. Its content-first architecture fits the task. The visual shell is specific to this portfolio: paper, ink, ruled divisions, and an asymmetric editorial grid.

The principle is simple: reuse the structure that earns its place, then make each visible decision serve the work.
